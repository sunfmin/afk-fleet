# Tools (`scripts/afk.py`) — the deterministic muscle

Disclosed reference for [`afk-fleet`](../SKILL.md): the full interface table for the deterministic
subcommands the launcher and the worker call. Every deterministic step in the skill is one of these
subcommands, and `afk cycle` runs a whole reconciliation pass of them — a tick — in order; the
launcher (an LLM) answers only the judgments that call returns (ADR-0004, ADR-0017, ADR-0028). Every decision is a pure
function in `afk_decide.py` (fixture-tested); `afk.py` only gathers their inputs and applies effects.

**The contract every subcommand shares:**

- It prints **one JSON object**. Exit 0 = it ran, and the result is a real answer (a lost claim race
  is `{"won": false}`, still exit 0). Exit 3 = `{"error": …}` — it could not do its job (auth,
  network, a rejected push, an unreadable remote, bad input, a bad command line), never an outcome
  to act on. No failure is reported as an empty or negative exit-0 result.
- It **requires `--config '<json>'`** — the canonical config from `afk config`, as returned by
  `afk probe` — and, when it touches GitHub, **`--repo <owner/name>`**. Pass both on every call; the
  table omits them. Only `afk config` and `afk worker-command` take no config (they run before one
  exists). Resolution is one order everywhere: `--set` → `--config` → the defaults table for keys
  the JSON omits (ADR-0009), and the result is validated like the config file is.
- `--set <key>=<value>` (repeatable) overrides one config key for one call, by the config file's own
  key name — `--set concurrency=1`, `--set gate.ci=local`. It is for tests and
  hand-debugging; a tick passes the run's `--config` and nothing else.
- `afk …` in this table is shorthand for the executable `<skill>/scripts/afk.py …` — one word, no
  interpreter in front, so it survives being held in a shell variable under zsh.
- The table's first column is **generated** from the parser — `scripts/gen_tools_doc.py` rewrites
  it, and a test fails while it is stale — so it is the authoritative flag list, same as
  `afk <subcommand> --help`. A test also fails if any `afk …` example in the skill names a
  subcommand or flag that does not exist.

| Subcommand | Does | Kind |
|---|---|---|
| **Bootstrap** | | |
| `afk config [--file <path>] [--defaults]` | parse + validate the repo config → **canonical JSON** (every key, defaults filled; unknown key → error). `--defaults` prints the one defaults table (ADR-0009) | pure (file read) |
| `afk probe [--base-branch <name>]` | the **claim namespace** that works (`refs/afk`, else the `refs/heads` fallback) and the **base branch** (ADR-0042), both folded into the returned **`config`**, which the launcher holds from then on → `{blocked, config, base}` (+ `detail`, the server's rejection, when `blocked`). Without `--base-branch`: `base: {status: ask, recorded, default_branch}` — the branch the last launch confirmed (kept on the remote, `refs/afk/base`; null when none) and the repo's default — and nothing below is checked. With it — the human's answer at this launch — the answer is put on record and `base: {status: settled, branch, recorded, default_branch}`; an error when the remote has no such branch, or when it is not the recorded one while any claim or live fleet instance stands on that. Then, in `gate.ci: local`, also the merge target's branch-`protection` verdict (ADR-0012) — which, unless `gate.adversarial_verify_prompt` is set, also refuses a target that would not take a batch's direct push: required pull-request reviews, push restrictions, a locked branch (ADR-0029) — and `gate_records: {verdict: ok \| warn, pruned, detail}`: whether a gate run can be put on record under `refs/afk/gate/` (a `warn` when the remote refuses it — every landing then gates itself), with the records more than a day old swept (ADR-0030) | effect + pure verdict |
| `afk worker-command [--check <cmd>]` | settle the string every worker is started with: ask-or-not (stock launcher → never asked) + the login shell's Claude-starting aliases to offer; `--check` resolves an answer's first word and flags a missing unattended flag (ADR-0010) | effect (login shell) + pure verdict |
| **The cycle** | | |
| `afk cycle [--state <json>] [--instance <id>] [--worker-command <cmd>] [--ready-timeout <s>] [--drain] [--wake]` | **one whole cycle** (ADR-0007, ADR-0017): digest observable state → tick-or-skip, and on a tick **run the reconciliation pass in code** — `rebuild` → `no-pr` → at most one `turn` → `nudge` / `turn --restart` / `fail` / `park` / `escalate` where the reason is on record → `release` of claims that outlived their issue and of `stale_closed` phantom locks → `reclaim` of `stale` → `dispatch` (continuations, then the frontier into the free slots) → `heartbeat` → `status` — then fold what it did into the state → `{action: tick\|skip, reason, state, sleep_seconds, progress, judgments}`. `reason` is `first` / `changed` / `forced` / `wake` (`--wake`: a wake arrived while the previous cycle was running, so this one ticks whatever the digest says) / `unsettled` (the last tick left a judgment, an error, or a PR that opened while it ran — that last one returns `sleep_seconds` 0) / `gate_off`, or `unchanged` on a skip, which also refreshes the lease when the fleet holds claims (`heartbeat`). `judgments` is what code cannot decide — `[{issue, kind, question, context, if_yes, if_no}]`, `kind` one of `empty_diff` / `no_checks` / `adversarial_verify` / `reason`, each answer a runnable `afk` command (for `reason` both are the same one: the answer is its `--reason` text), `bulky: true` on one to delegate; with any open, `sleep_seconds` is 0. `errors` (when any) lists transitions that failed — `[{step, issue, error}]` — with their claims still held. The pass reads each thing once — the open PRs, the claim refs, a PR's turn comment — and what it writes is in every read after it; the workers it starts are begun in turn and then waited for together, and a start that cannot begin ends the starting for that tick. `state` is opaque and handed back verbatim; after a tick it holds the digest of the fleet as that tick left it (its own boards, refs and markers do not cause the next one) and which status board each claim already shows (an unchanged one costs no read); it carries `--instance` and `--worker-command`, which are passed on the first cycle only (no `--state`: a first cycle, always a tick) — a `state` without them, or one beside a different value of either, is exit 3. Sleep is `pace`'s: busy, or idle after three empty cycles. `--drain` is the run's **last** cycle — the launcher's stop: no gate, no pass; it releases every claim of mine that no open PR stands behind (a worker still coding, an orphan, a `closed` row) and keeps those with an open PR → `{action: drain, reason: stop, state, sleep_seconds: null, progress, judgments: []}`, a failed release in `errors` with its claim still held | effect + pure verdict |
| **Observation (read-only)** | | |
| `afk rebuild --instance <id>` | **one call → the whole working set**, from three reads made at once — every open issue (all pages, pull requests left out, each with its open-blocker count: no read per frontier candidate), the open PRs, the claim refs: frontier (dispatch+excluded), `mine` subclassified (`awaiting_turn` / `landing` / `awaiting_ci` / `failure` / `no_pr` / `closed`) with PR/checks, the `attempt` it is on, `starting` (its failure is counted and the fresh worker has not started: a retry cut short, which the tick finishes with `afk fail`), and the `board_phase` it renders as, `peer_live`, `stale` (a dead peer's claim on an open issue, with the sha reclaim needs), `stale_closed` (a dead peer's claim on an issue already closed — a phantom lock — with the sha release needs), `free_slots`, fingerprint (ADR-0008). In `gate.ci: local` an open PR is `awaiting_turn` outright — no checks are read (ADR-0012). `merge_order` lists my ready PRs' issues in the order landing turns are granted: the PR that holds the turn first, then the lower PR number. A PR that holds my landing turn is `landing`, and its row's `stopped` is the outcome its worker's last `afk land` stopped with, null while it has not stopped (ADR-0027). A PR in a **merge batch** (ADR-0029) that holds my turn is `landing` too, and its row's `batch` is `{id, members, phase}` — the phase one of `stacking` / `gating` / `fixing`; `batches` lists each batch a PR of my claims is in (`{id, instance, members, phase, at}` — an `instance` that is not mine is a dead fleet's batch on claims I took); a row's `unbatched` says the PR left a batch (`left_out` / `abandoned` / `dissolved`): it leads `merge_order` and is never batched again | effect gather + pure assembly |
| `afk no-pr [--issue <n>] [--batch <batch>] [--worktree <path>]` | **why my claims have no PR** — or, for a `landing` claim, whether its worker is still landing — for every such claim in one call → `{workers: [row per --issue]}`. Each worker's **worker state** is read first from `orca worktree ps` (its runtime's own report, checked against its terminal's output; ADR-0021): busy or gone is settled from that alone, no GitHub read (so its `turn_at` is null: not read). For a stopped worker it finds the issue's worktree through orca (`--worktree` overrides, one --issue only), reads its git progress against the remote base tip, the worker's latest `afk:verdict` marker, where each issue it says it is blocked by stands — the issue itself, the claim refs, the open PRs and the chain of open blockers under it (the cycle check) — and the landing turn on its PR → each row `{outcome, action, idle_seconds, pending_blockers, worktree, progress, worker_verdict, blockers, nudged_at, turn_at, worker_state}` (coding / idle_done / idle_blocked / idle_undecided / idle_stalled / idle_failed / dead; `worker_verdict` is the marker the worker posted — an input, not the conclusion; `blockers` is `[{number, standing: closed\|waiting\|unmet, reason}]`, and `idle_blocked` is `redispatch`, `park` or `escalate` by them — ADR-0022; `idle_undecided` / `escalate` is a `needs-decision` verdict: the issue's owner has a decision to make, and no attempt is spent on it — ADR-0041). A worker whose landing stopped for the tick (`awaiting_ci` / `needs_verify` / `no_checks`) is `coding` / `leave`: `afk turn` is what moves it. A `landing` claim's worker still silent after its nudge is `idle_stalled` / `restart` — a worker restarted onto the turn (`afk turn --restart`), not an attempt spent — once per turn: with the restart already on the turn marker the same silence is `idle_stalled` / `escalate` — the claim escalated with its PR, branch and worktree kept (`afk escalate`), never `idle_failed` / `next_attempt`: no silence of a `landing` claim reaches `afk fail` (ADR-0035). The tick supplies nothing but the issue numbers; an orca that cannot be asked is an error, never "gone". `--batch <batch>` asks the same of a merge batch's worker, from the batch's worktree → one row `{batch, outcome, action, …}`: left while busy or within grace of its turn or its last `afk land --batch`, continued when gone, nudged once when silent, and silent again the batch is abandoned (ADR-0029) | effect gather + pure verdict |
| `afk recovery --issue <n> [--branch <branch>] [--worktree <path>] [--no-worktree]` | what `afk dispatch` would continue from, without acting: a **dead** claim's recoverable progress → the tiered **continuation** verdict `{tier, action, prompt, reason, worktree, branch}` (worktree still here? branch ahead of base?). A remote that cannot be read is an error, never tier 3 — ADR-0011 | effect gather + pure verdict |
| **Act — one call per transition (ADR-0017)** | | |
| `afk dispatch --issue <n> --instance <id> --worker-command <cmd> [--ready-timeout <s>] [--start <auto\|fresh>]` | **start a worker**: claim (or confirm the claim is mine) → continuation tier → orca worktree at the right commit (the remote base tip, the pushed branch tip, or the worktree still here) → agent started with the worker launch command → prompt filled, delivered and submitted → status board. `{started: true, claim: won\|held, tier, action, prompt, worktree, branch, terminal}`, or `{started: false, claim: lost, owner}`. `--start fresh` discards the previous attempt first | effect + pure verdicts |
| `afk turn [--issue <n>] --instance <id> --worker-command <cmd> [--ready-timeout <s>] [--batch] [--abandon <batch>] [--verified <head>] [--allow-no-checks] [--restart]` | **give a PR the landing turn** — the tick's half of a landing, one PR at a time (ADR-0027): refuse while another claim of mine holds the turn (`waiting`, with `holder`) or the tick's judgments are not in (the PR's checks in `required`, `--allow-no-checks`, `--verified <head>`) → write the landing brief → record the turn as ONE marker comment on the PR → deliver it — one submitted line to the worker's terminal, or, when that is gone, a new worker started by continuation in the same worktree (or one recreated at the PR's head), briefed only to land → status board. Run again on a `landing` row whose worker stopped for the tick, it tells that worker to land again (`again: true`). `{outcome: granted \| waiting \| landing \| awaiting_ci \| gate_red \| no_checks \| needs_verify, pr, head, delivery: terminal\|continuation, terminal, worktree, comment_id}`. It never merges, and there is no launcher-side merge fallback. **`--restart`** is for a `landing` row whose worker is still silent after its nudge (`no-pr` → `idle_stalled` / `restart`, ADR-0035): the idle session is closed and a worker is started by continuation in the same worktree (or one recreated at the PR's head, never from base), briefed only to land — the delivery a gone terminal gets — and the restart is written on the turn marker (`restarted`, also in the result). The PR, the branch, the worktree and the `afk-attempt/<n>` label are untouched; once per turn — a second call is refused, and a restarted worker silent again after its own nudge is escalated with the PR kept (`afk escalate`), never failed. A PR that holds no turn of mine is refused. **`--batch`** gives the turn to a **merge batch** instead (ADR-0029; `gate.ci: local`): when no turn is out and two or more of my ready PRs are eligible — not owing an adversarial verify, never batched before, their own worker not still working — it records ONE batch marker on every member PR, has orca create the batch's own worktree at the target's tip, and starts a **batch worker** there on the batch brief → `{outcome: granted, batch, issues, prs, again, delivery: fresh\|worktree\|branch, terminal, worktree}`; `too_few` when fewer than two are eligible (the turn goes to one PR), `waiting` while one PR holds the turn, `landing` while my batch's worker is there; a batch whose worker has no terminal is continued — in its worktree, else from its pushed branch. **`--abandon <batch>`** gives a batch up with nothing landed: every member's marker is replaced by one that holds no turn, the batch's worktree and pushed branch are removed → `{outcome: abandoned, batch, issues, prs, deleted_branches}`; its PRs take single turns and are not batched again | effect + pure verdicts |
| **The worker's own** | | |
| `afk gate [--gate-timeout <s>]` | **a worker's run of the local gate**, in the worktree it is called from — never run by a tick. Runs `gate.local_command`, streams its log to the terminal (stderr), and on **green**, on a committed tree, puts the run on record on the remote — one ref, `refs/afk/gate/<tree>-<hash of the command>`, named for the tree it tested; a red or timed-out run leaves no record (and deletes that tree's). `{status: green \| red, exit_code, timed_out, command, head, recorded, detail}` — `recorded` is true only for a green run on a tree with nothing uncommitted or untracked whose record was written (`not_recorded` says why it was not: the worker goes on, and the landing gates), the one kind `afk land` trusts (ADR-0030). The worker prompt carries the whole line, config included | effect + pure verdict |
| `afk land [--issue <n>] [--batch <batch>] [--gate-timeout <s>] [--excerpt-lines <k>] [--merged-timeout <s>] [--checks-timeout <s>] [--checks-poll <s>]` | **a worker lands its own PR**, in the worktree it is called from — never run by a tick, and the only way a PR lands (ADR-0027). Exit 3, nothing changed, unless the PR holds the landing turn of the fleet instance that holds the issue's claim. Then: sync (merge the target in, never rebase) → push → the configured machine gate on that head (in `local`: run here, or not run again when a green run of the configured command is on record on the remote for that head's tree, wherever it was made — `gate.source: run \| recorded`, ADR-0030; in `required`: the PR's checks on that head, **waited for here** — re-read every `--checks-poll` seconds, default 15, for at most `--checks-timeout`, default 1800 — whenever the sync pushed a new head or they are still running) → adversarial-verify check → `gh pr merge` pinned to the gated head → status board. `{outcome: merged \| conflict \| gate_red \| awaiting_ci \| needs_verify \| no_checks, pr, head, synced, gate, …}`: `conflict` leaves the merge in progress with `files` for the worker to resolve and commit; `gate_red` is the worker's to fix; `awaiting_ci` is only what the wait for checks says when its bound runs out; on `awaiting_ci` / `needs_verify` / `no_checks` the worker wakes the launcher and stops, and the tick's next `afk turn` tells it to land again. No outcome spends an attempt or gives the turn up; each one but `merged` is written onto the PR's turn comment. It releases no claim and removes no worktree — the next cycle's `closed` row does. The landing brief carries the whole line, config included. **`--batch <batch>`** is the **batch worker's** landing, in the batch's worktree (ADR-0029) — which keeps no list of the batch's PRs: the members are read, on every run, from the turn markers the PRs carry. Exit 3, nothing changed, unless every member PR carries the batch's turn marker naming the instance that holds its claim. Then: stack — reset to the target's tip, ONE merge commit per member PR in merge order, its second parent the PR's own head (`Title (#pr)`, `Closes #issue`), the fix commits already made put back on top; a PR that conflicts with the stack is left out → push the stack to the batch's branch → the gate ONCE on the stack (not at all when that stack's tree is already on record green) → push it to the target as a fast-forward (the only lock: a target that moved refuses it) → per member: status board, issue closed; GitHub shows each PR merged by itself, and its branch is deleted once it does (waited for up to `--merged-timeout`; `unmerged` lists the PRs still open then, left with their branches) (ADR-0034). `{outcome: landed \| gate_red \| target_moved \| too_small, batch, issues, prs, left_out: [{issue, pr, reason, files}], fix_commits, landed: [{issue, pr, commit}]}`: `gate_red` is fixed with one more commit on top and run again; `target_moved` is run again (re-stacked, re-gated); `too_small` dissolves the batch. Nothing lands on any outcome but `landed` | effect + pure verdicts |
| `afk nudge [--issue <n>] --instance <id> [--batch <batch>] [--worktree <path>]` | **tell a silent worker to carry on** (`no-pr` → `idle_stalled`): read the last screen of its terminal, type one line at it, record the nudge in the worktree's git dir → `{action: nudged, terminal, terminal_tail}`. Once per worker — a second call is refused; no attempt is spent, nothing is discarded (ADR-0018). `--batch <batch>` nudges a merge batch's worker the same way, once per batch | effect |
| `afk fail --issue <n> --instance <id> --worker-command <cmd> [--ready-timeout <s>] --reason <text>` | **the retry ladder**: read the attempt off the issue, then `retry` (swap the `afk-attempt/<n>` label up by one and add `afk-attempt/starting` in one edit, discard the failed attempt's PR + branch + worktree, start a fresh worker handed `--reason`, remove `afk-attempt/starting`) or `escalate` (as below) → `{action, attempt, …}`. Run again on a failure already counted — the issue still carries `afk-attempt/starting` — it finishes that retry and adds nothing: one failure, one attempt. After an unanswered nudge the worker's last screen is appended to the reason. A `landing` claim's silence never comes here — it is restarted onto its turn, then escalated (ADR-0035); `fail` reaches a landing claim only by the tick's own judgments | effect + pure verdict |
| `afk escalate --issue <n> --instance <id> --reason <text>` | **hand a claim to a human**, in one order: status board → relabel (`escalate_label` on; `ready_label` and attempt labels off) → comment → release the claim → remove the worktree when its branch holds no work (one with commits or a dirty tree is kept, as `park` keeps it) — for a blocker nothing will resolve (`no-pr` → `idle_blocked` / `escalate`), a decision only the issue's owner can make (`no-pr` → `idle_undecided` / `escalate`, ADR-0041), or a landing turn silent again past its one restart (`no-pr` → `idle_stalled` / `escalate`, ADR-0035): the PR stays open, the branch and the worktree stay, no attempt is spent, and a released claim holds no turn, so the next PR's `turn` is `granted`. After an unanswered nudge the worker's last screen is appended to the reason, as `fail` appends it | effect |
| `afk park --issue <n> --instance <id>` | **wait on a dependency the worker discovered** (`no-pr` → `idle_blocked` / `park`), in one order: a native `blocked_by` edge to each named blocker still open → status board → release the claim → remove the worktree when its branch holds no work (one with commits or a dirty tree is kept). `{action: parked, blocked_by, edges_added, released, cleanup}`. `ready_label` and the attempt labels are untouched; the frontier excludes the issue until its blockers close. Re-reads the blockers and refuses a claim that is not parkable (ADR-0022) | effect + pure verdict |
| `afk close --issue <n> --instance <id>` | **close an issue that needed no change** (after the tick verified the empty diff): status board → close → release → worktree cleanup | effect |
| `afk status <n> --phase <phase> [--instance <id>] [--pr <pr>] [--attempt <k>]` | upsert the human-facing progress **status board** comment at a non-terminal phase, idempotently. `<phase>` is a `mine` row's `board_phase`; `<k>` is the row's `attempt`; `retry_max` and the gate's name come from config. (The terminal phases are written by `land` / `escalate` / `park` / `close`, `landing` by `turn`.) | pure render + effect |
| **Claim refs** | | |
| `afk reclaim <n> --instance <id> --expect-sha <sha>` | `--force-with-lease` take of a stale claim → `{won}`. For a `stale` row; a `stale_closed` one is released instead | effect |
| `afk takeover --instance <id> [--list] [--from <dead-id>] [--yes]` | the fleet instances GitHub remembers (claim markers + heartbeat refs) with heartbeat age / host / claim count — or force-take a dead one's claims: same atomic push as `reclaim`, staleness gate skipped, a fresh-heartbeat target held back until `--yes` (ADR-0011). `--instance` is always **my** id | effect + pure verdict |
| `afk release <n> --instance <id> [--expect-sha <sha>]` | delete a claim ref → `{released: true}` (idempotent: already gone counts). A delete that left the claim on the remote is an error. For the cases no transition covers. Without `--expect-sha`, a claim of **mine** — an orphan-release, a `closed` row, the drain; a claim another instance holds is refused. A claim whose issue is closed — the `closed` row a landed PR leaves — has its worktree removed too (`cleanup`); an open issue's worktree is never touched; and a PR a merge batch landed that GitHub still does not show merged is closed here, with the comment naming its commit (`closed_pr`, ADR-0029, ADR-0034); and the local `base_branch` branch of the fleet's own checkout is fast-forwarded to what landed (`synced`: `{branch, tip, updated}` or `{branch, skipped}`, ADR-0037). With `--expect-sha`, a `stale_closed` row: the dead peer's claim is deleted only while it still points at the sha rebuild reported, and a claim that moved is an error | effect |
| `afk heartbeat --instance <id>` | refresh my heartbeat if due → `{refreshed}` | effect |
| `afk claim <n> --instance <id>` | low-level: atomic create-or-lose the claim ref → `{won}` (`won: false` names the `owner`; a push that failed for any other reason is an error). A tick never calls it — `dispatch` does | effect |
| `afk scan` | debug only: every claim + heartbeat ref as read from the remote (an unreadable remote is an error, not an empty list). A tick never calls it — `rebuild` does | effect |
| `afk classify-claims --instance <id>` | debug only: the mine / peer_live / stale partition on its own. A tick never calls it — `rebuild` does | effect gather + pure verdict |

Judgment stays with the launcher and is **not** a tool: is the implementation correct (the gate),
adversarial verify, whether a
recovered worktree is sane to build on, landing a PR that has no checks, the reason a failure or an
escalation is given. Each of those is exactly where a transition stops and
returns an `outcome`, or the one argument (`--reason`, `--verified`, `--start fresh`,
`--allow-no-checks`) it takes from you.
