# Tools (`scripts/afk.py`) — the deterministic muscle

Disclosed reference for [`afk-fleet`](../SKILL.md): the full interface table for the deterministic
subcommands the launcher and tick call. Every deterministic step in the skill is one of these
subcommands, and `afk cycle` runs a whole reconciliation pass of them in order; the tick (an LLM)
answers only the judgments that call returns (ADR-0004, ADR-0017). Every decision is a pure
function in `afk_decide.py` (fixture-tested); `afk.py` only gathers their inputs and applies effects.

**The contract every subcommand shares:**

- It prints **one JSON object**. Exit 0 = it ran, and the result is a real answer (a lost claim race
  is `{"won": false}`, still exit 0). Exit 3 = `{"error": …}` — it could not do its job (auth,
  network, a rejected push, an unreadable remote, bad input, a bad command line), never an outcome
  to act on. No failure is reported as an empty or negative exit-0 result.
- It **requires `--config '<json>'`** — the canonical config from `afk config`, as returned by
  `afk probe` — and, when it touches GitHub, **`--repo <owner/name>`**. Pass both on every call; the
  table omits them. Only `afk config` and `afk worker-command` take no config (they run before one
  exists). Resolution is one order everywhere: `--set` → `--config` → the defaults table for keys
  the JSON omits (ADR-0009), and the result is validated like the config file is.
- `--set <key>=<value>` (repeatable) overrides one config key for one call, by the config file's own
  key name — `--set claim_lease_ttl_seconds=60`, `--set gate.ci=local`. It is for tests and
  hand-debugging; a tick passes the run's `--config` and nothing else.
- `afk …` in this table is shorthand for the executable `<skill>/scripts/afk.py …` — one word, no
  interpreter in front, so it survives being held in a shell variable under zsh.
- The table's first column is **generated** from the parser — `scripts/gen_tools_doc.py` rewrites
  it, and a test fails while it is stale — so it is the authoritative flag list, same as
  `afk <subcommand> --help`. A test also fails if any `afk …` example in the skill names a
  subcommand or flag that does not exist.

| Subcommand | Does | Kind |
|---|---|---|
| **Bootstrap** | | |
| `afk config [--file <path>] [--defaults]` | parse + validate the repo config → **canonical JSON** (every key, defaults filled; unknown key → error). `--defaults` prints the one defaults table (ADR-0009) | pure (file read) |
| `afk probe` | the **claim namespace** that works (`refs/afk`, else the `refs/heads` fallback) folded into the returned **`config`**, which the launcher holds from then on → `{blocked, config}` (+ `detail`, the server's rejection, when `blocked`); in `gate.ci: local`, also the merge target's branch-`protection` verdict (ADR-0012) | effect + pure verdict |
| `afk worker-command [--check <cmd>]` | settle the string every worker is started with: ask-or-not (stock launcher → never asked) + the login shell's Claude-starting aliases to offer; `--check` resolves an answer's first word and flags a missing unattended flag (ADR-0010) | effect (login shell) + pure verdict |
| **The cycle** | | |
| `afk cycle [--state <json>] [--instance <id>] [--worker-command <cmd>] [--ready-timeout <s>]` | **one whole cycle** (ADR-0007, ADR-0017): digest observable state → tick-or-skip, and on a tick **run the reconciliation pass in code** — `rebuild` → `no-pr` → at most one `turn` → `nudge` / `fail` / `park` / `escalate` where the reason is on record → `release` of claims that outlived their issue and of `stale_closed` phantom locks → `reclaim` of `stale` → `dispatch` (continuations, then the frontier into the free slots) → `heartbeat` → `status` — then fold what it did into the state → `{action: tick\|skip, reason, state, sleep_seconds, progress, judgments}`. `reason` is `first` / `changed` / `forced` / `unsettled` (the last tick left a judgment or an error) / `gate_off`, or `unchanged` on a skip, which also refreshes the lease when the fleet holds claims (`heartbeat`). `judgments` is what code cannot decide — `[{issue, kind, question, context, if_yes, if_no}]`, `kind` one of `empty_diff` / `no_checks` / `adversarial_verify` / `reason`, each answer a runnable `afk` command (for `reason` both are the same one: the answer is its `--reason` text), `bulky: true` on one to delegate; with any open, `sleep_seconds` is 0. `errors` (when any) lists transitions that failed — `[{step, issue, error}]` — with their claims still held. `state` is opaque and handed back verbatim; it carries `--instance` and `--worker-command`, which are passed on the first cycle only (no `--state`: a first cycle, always a tick) — a `state` without them, or one beside a different value of either, is exit 3. Sleep is `pace`'s: busy / idle after `idle_ticks_before_sleep` empty cycles / never past `ttl/2` while a claim is held | effect + pure verdict |
| **Observation (read-only)** | | |
| `afk rebuild --instance <id>` | **one call → the whole working set**: frontier (dispatch+excluded), `mine` subclassified (`awaiting_turn` / `landing` / `awaiting_ci` / `failure` / `no_pr` / `closed`) with PR/checks, the `attempt` it is on, and the `board_phase` it renders as, `peer_live`, `stale` (a dead peer's claim on an open issue, with the sha reclaim needs), `stale_closed` (a dead peer's claim on an issue already closed — a phantom lock — with the sha release needs), `free_slots`, fingerprint (ADR-0008). In `gate.ci: local` an open PR is `awaiting_turn` outright — no checks are read (ADR-0012). `merge_order` lists my ready PRs' issues in the order landing turns are granted: the PR that holds the turn first, then the lower PR number. A PR that holds my landing turn is `landing`, and its row's `stopped` is the outcome its worker's last `afk land` stopped with, null while it has not stopped (ADR-0027) | effect gather + pure assembly |
| `afk no-pr --issue <n> [--worktree <path>]` | **why my claims have no PR** — or, for a `landing` claim, whether its worker is still landing — for every such claim in one call → `{workers: [row per --issue]}`. Each worker's **worker state** is read first from `orca worktree ps` (its runtime's own report, checked against its terminal's output; ADR-0021): busy or gone is settled from that alone, no GitHub read (so its `turn_at` is null: not read). For a stopped worker it finds the issue's worktree through orca (`--worktree` overrides, one --issue only), reads its git progress against the remote base tip, the worker's latest `afk:verdict` marker, where each issue it says it is blocked by stands — the issue itself, the claim refs, the open PRs and the chain of open blockers under it (the cycle check) — and the landing turn on its PR → each row `{outcome, action, idle_seconds, pending_blockers, worktree, progress, worker_verdict, blockers, nudged_at, turn_at, worker_state}` (coding / idle_done / idle_blocked / idle_stalled / idle_failed / dead; `worker_verdict` is the marker the worker posted — an input, not the conclusion; `blockers` is `[{number, standing: closed\|waiting\|unmet, reason}]`, and `idle_blocked` is `redispatch`, `park` or `escalate` by them — ADR-0022). A worker whose landing stopped for the tick (`awaiting_ci` / `needs_verify` / `no_checks`) is `coding` / `leave`: `afk turn` is what moves it. The tick supplies nothing but the issue numbers; an orca that cannot be asked is an error, never "gone" | effect gather + pure verdict |
| `afk recovery --issue <n> [--branch <branch>] [--worktree <path>] [--no-worktree]` | what `afk dispatch` would continue from, without acting: a **dead** claim's recoverable progress → the tiered **continuation** verdict `{tier, action, prompt, reason, worktree, branch}` (worktree still here? branch ahead of base?). A remote that cannot be read is an error, never tier 3 — ADR-0011 | effect gather + pure verdict |
| **Act — one call per transition (ADR-0017)** | | |
| `afk dispatch --issue <n> --instance <id> --worker-command <cmd> [--ready-timeout <s>] [--start <auto\|fresh>]` | **start a worker**: claim (or confirm the claim is mine) → continuation tier → orca worktree at the right commit (the remote base tip, the pushed branch tip, or the worktree still here) → agent started with the worker launch command → prompt filled, delivered and submitted → status board. `{started: true, claim: won\|held, tier, action, prompt, worktree, branch, terminal}`, or `{started: false, claim: lost, owner}`. `--start fresh` discards the previous attempt first | effect + pure verdicts |
| `afk turn --issue <n> --instance <id> --worker-command <cmd> [--ready-timeout <s>] [--verified <head>] [--allow-no-checks]` | **give a PR the landing turn** — the tick's half of a landing, one PR at a time (ADR-0027): refuse while another claim of mine holds the turn (`waiting`, with `holder`) or the tick's judgments are not in (the PR's checks in `required`, `--allow-no-checks`, `--verified <head>`) → write the landing brief → record the turn as ONE marker comment on the PR → deliver it — one submitted line to the worker's terminal, or, when that is gone, a new worker started by continuation in the same worktree (or one recreated at the PR's head), briefed only to land → status board. Run again on a `landing` row whose worker stopped for the tick, it tells that worker to land again (`again: true`). `{outcome: granted \| waiting \| landing \| awaiting_ci \| gate_red \| no_checks \| needs_verify, pr, head, delivery: terminal\|continuation, terminal, worktree, comment_id}`. It never merges, and there is no launcher-side merge fallback | effect + pure verdicts |
| **The worker's own** | | |
| `afk gate [--gate-timeout <s>]` | **a worker's run of the local gate**, in the worktree it is called from — never run by a tick. Runs `gate.local_command`, streams its log to the terminal (stderr), and on **green** records the head and the command in the worktree's git dir; a red or timed-out run leaves no record (and drops the one before it). `{status: green \| red, exit_code, timed_out, command, head, recorded, detail}` — `recorded` is true only for a green run on a tree with nothing uncommitted or untracked, the one kind `afk land` may trust (ADR-0026). The worker prompt carries the whole line, config included | effect + pure verdict |
| `afk land --issue <n> [--gate-timeout <s>] [--excerpt-lines <k>]` | **a worker lands its own PR**, in the worktree it is called from — never run by a tick, and the only way a PR lands (ADR-0027). Exit 3, nothing changed, unless the PR holds the landing turn of the fleet instance that holds the issue's claim. Then: sync (merge the target in, never rebase) → push → the configured machine gate on that head (in `local`: run here, or, with `gate.trust_recorded_run`, not run again when a green run is on record for exactly that head — `gate.source: run \| recorded`, ADR-0026; in `required`: the PR's checks) → adversarial-verify check → `gh pr merge` pinned to the gated head → status board. `{outcome: merged \| conflict \| gate_red \| awaiting_ci \| needs_verify \| no_checks, pr, head, synced, gate, …}`: `conflict` leaves the merge in progress with `files` for the worker to resolve and commit; `gate_red` is the worker's to fix; on `awaiting_ci` / `needs_verify` / `no_checks` the worker wakes the launcher and stops, and the tick's next `afk turn` tells it to land again. No outcome spends an attempt or gives the turn up; each one but `merged` is written onto the PR's turn comment. It releases no claim and removes no worktree — the next cycle's `closed` row does. The landing brief carries the whole line, config included | effect + pure verdicts |
| `afk nudge --issue <n> --instance <id> [--worktree <path>]` | **tell a silent worker to carry on** (`no-pr` → `idle_stalled`): read the last screen of its terminal, type one line at it, record the nudge in the worktree's git dir → `{action: nudged, terminal, terminal_tail}`. Once per worker — a second call is refused; no attempt is spent, nothing is discarded (ADR-0018) | effect |
| `afk fail --issue <n> --instance <id> --worker-command <cmd> [--ready-timeout <s>] --reason <text>` | **the retry ladder**: read the attempt off the issue, then `retry` (swap the `afk-attempt/*` label, discard the failed attempt's PR + branch + worktree, start a fresh worker handed `--reason`) or `escalate` (as below) → `{action, attempt, …}`. After an unanswered nudge the worker's last screen is appended to the reason | effect + pure verdict |
| `afk escalate --issue <n> --instance <id> --reason <text>` | **hand a claim to a human**, in one order: status board → relabel (`escalate_label` on; `ready_label` and attempt labels off) → comment → release the claim last | effect |
| `afk park --issue <n> --instance <id>` | **wait on a dependency the worker discovered** (`no-pr` → `idle_blocked` / `park`), in one order: a native `blocked_by` edge to each named blocker still open → status board → release the claim → remove the worktree when its branch holds no work (one with commits or a dirty tree is kept). `{action: parked, blocked_by, edges_added, released, cleanup}`. `ready_label` and the attempt labels are untouched; the frontier excludes the issue until its blockers close. Re-reads the blockers and refuses a claim that is not parkable (ADR-0022) | effect + pure verdict |
| `afk close --issue <n> --instance <id>` | **close an issue that needed no change** (after the tick verified the empty diff): status board → close → release → worktree cleanup | effect |
| `afk status <n> --phase <phase> [--instance <id>] [--pr <pr>] [--attempt <k>]` | upsert the human-facing progress **status board** comment at a non-terminal phase, idempotently. `<phase>` is a `mine` row's `board_phase`; `<k>` is the row's `attempt`; `retry_max` and the gate's name come from config. (The terminal phases are written by `land` / `escalate` / `park` / `close`, `landing` by `turn`.) | pure render + effect |
| **Claim refs** | | |
| `afk reclaim <n> --instance <id> --expect-sha <sha>` | `--force-with-lease` take of a stale claim → `{won}`. For a `stale` row; a `stale_closed` one is released instead | effect |
| `afk takeover --instance <id> [--list] [--from <dead-id>] [--yes]` | the fleet instances GitHub remembers (claim markers + heartbeat refs) with heartbeat age / host / claim count — or force-take a dead one's claims: same atomic push as `reclaim`, staleness gate skipped, a fresh-heartbeat target held back until `--yes` (ADR-0011). `--instance` is always **my** id | effect + pure verdict |
| `afk release <n> --instance <id> [--expect-sha <sha>]` | delete a claim ref → `{released: true}` (idempotent: already gone counts). A delete that left the claim on the remote is an error. For the cases no transition covers. Without `--expect-sha`, a claim of **mine** — an orphan-release, a `closed` row, the drain; a claim another instance holds is refused. A claim whose issue is closed — the `closed` row a landed PR leaves — has its worktree removed too (`cleanup`, when `worktree_cleanup`); an open issue's worktree is never touched. With `--expect-sha`, a `stale_closed` row: the dead peer's claim is deleted only while it still points at the sha rebuild reported, and a claim that moved is an error | effect |
| `afk heartbeat --instance <id>` | refresh my heartbeat if due → `{refreshed}` | effect |
| `afk claim <n> --instance <id>` | low-level: atomic create-or-lose the claim ref → `{won}` (`won: false` names the `owner`; a push that failed for any other reason is an error). A tick never calls it — `dispatch` does | effect |
| `afk scan` | debug only: every claim + heartbeat ref as read from the remote (an unreadable remote is an error, not an empty list). A tick never calls it — `rebuild` does | effect |
| `afk classify-claims --instance <id>` | debug only: the mine / peer_live / stale partition on its own. A tick never calls it — `rebuild` does | effect gather + pure verdict |

Judgment stays with the tick and is **not** a tool: is the implementation correct (the gate),
adversarial verify, whether a
recovered worktree is sane to build on, landing a PR that has no checks, the reason a failure or an
escalation is given. Each of those is exactly where a transition stops and
returns an `outcome`, or the one argument (`--reason`, `--verified`, `--start fresh`,
`--allow-no-checks`) it takes from you.
