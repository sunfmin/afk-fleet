# Tools (`scripts/afk.py`) — the deterministic muscle

Disclosed reference for [`afk-fleet`](../SKILL.md): the full interface table for the deterministic
subcommands the launcher and the worker call. Every deterministic step in the skill is one of these
subcommands, and `afk cycle` runs a whole reconciliation pass of them — a tick — in order; the
launcher (an LLM) answers only the judgments that call returns (ADR-0004, ADR-0017, ADR-0028). Every decision is a pure
function in `afk_decide.py` (fixture-tested); `afk.py` only gathers their inputs and applies effects.

**The contract every subcommand shares:**

- It prints **one JSON object**. Exit 0 = it ran, and the result is a real answer (a lost claim race
  is `{"won": false}`, still exit 0). Exit 3 = `{"error": …}` — it could not do its job (auth,
  network, a rejected push, an unreadable remote, bad input, a bad command line), never an outcome
  to act on. No failure is reported as an empty or negative exit-0 result.
- It **requires `--config '<json>'`** — the canonical config from `afk config`, as returned by
  `afk probe` — and, when it touches GitHub, **`--repo <owner/name>`**. Pass both on every call; the
  table omits them. Only `afk config` and `afk worker-command` take no config (they run before one
  exists). Resolution is one order everywhere: `--set` → `--config` → the defaults table for keys
  the JSON omits (ADR-0009), and the result is validated like the config file is. The JSON itself
  is held to the file's schema: an unknown, renamed or removed key, or a value of the wrong type, is
  an `{"error": …}` naming the key — never dropped, never defaulted.
- `--set <key>=<value>` (repeatable) overrides one config key for one call, by the config file's own
  key name — `--set concurrency=1`, `--set gate.ci=local`. Its value is typed as the file's is,
  except that a string is taken verbatim, quotes and `#` included: the shell already unquoted
  it and cut its comment. It is for tests and
  hand-debugging; a tick passes the run's `--config` and nothing else.
- `afk …` in this table is shorthand for the executable `<skill>/scripts/afk.py …` — one word, no
  interpreter in front, so it survives being held in a shell variable under zsh.
- The table's first column is **generated** from the parser — `scripts/gen_tools_doc.py` rewrites
  it, and a test fails while it is stale — so it is the authoritative flag list, same as
  `afk <subcommand> --help`. A test also fails if any `afk …` example in the skill names a
  subcommand or flag that does not exist.

| `afk config [--file <path>] [--defaults]` | parse + validate the repo config → **canonical JSON** (every key, defaults filled; unknown key → error). `--defaults` prints the one defaults table (ADR-0009) | pure (file read) |
| `afk probe [--base-branch <name>]` | the **claim namespace** that works (`refs/afk`, else the `refs/heads` fallback) and the **base branch** (ADR-0042), both folded into the returned **`config`**, which the launcher holds from then on → `{blocked, config, base}` (+ `detail`, the server's rejection, when `blocked`). Without `--base-branch`: `base: {status: ask, recorded, default_branch}` — the branch the last launch confirmed (kept on the remote, `refs/afk/base`; null when none) and the repo's default — and nothing below is checked. With it — the human's answer at this launch — the answer is put on record and `base: {status: settled, branch, recorded, default_branch}`; an error when the remote has no such branch, or when it is not the recorded one while any claim or live fleet instance stands on that. Then, in `gate.ci: local`, also the merge target's branch-`protection` verdict (ADR-0012) — which, unless `gate.adversarial_verify_prompt` is set, also refuses a target that would not take the landing train's direct push: required pull-request reviews, push restrictions, a locked branch (ADR-0048) — and `gate_records: {verdict: ok \| warn, pruned, detail}`: whether a gate run can be put on record under `refs/afk/gate/` (a `warn` when the remote refuses it — every landing then gates itself), with the records more than a day old swept (ADR-0030) | effect + pure verdict |
| `afk worker-command [--check <cmd>]` | settle the string every worker is started with: ask-or-not (stock launcher → never asked) + the login shell's Claude-starting aliases to offer; `--check` resolves an answer's first word and flags a missing unattended flag (ADR-0010) | effect (login shell) + pure verdict |
| **The cycle** | | |
| `afk cycle [--state <json>] [--instance <id>] [--worker-command <cmd>] [--ready-timeout <s>] [--drain] [--wake]` | **one whole cycle** (ADR-0007, ADR-0017): digest observable state → tick-or-skip, and on a tick **run the reconciliation pass in code** — `rebuild` → `no-pr` → at most one `turn` → `nudge` / `turn --restart` / `fail` / `park` / `escalate` where the reason is on record → `release` of claims that outlived their issue and of `stale_closed` phantom locks → `reclaim` of `stale` → `dispatch` (continuations, then the frontier into the free slots) → `heartbeat` → `status` — then fold what it did into the state → `{action: tick\|skip, reason, state, sleep_seconds, progress, judgments}`. `reason` is `first` / `changed` / `forced` / `wake` (`--wake`: a wake arrived while the previous cycle was running, so this one ticks whatever the digest says) / `unsettled` (the last tick left a judgment, an error, or a PR that opened while it ran — that last one returns `sleep_seconds` 0) / `gate_off`, or `unchanged` on a skip, which also refreshes the lease when the fleet holds claims (`heartbeat`). `judgments` is what code cannot decide — `[{issue, kind, question, context, if_yes, if_no}]`, `kind` one of `empty_diff` / `no_checks` / `adversarial_verify` / `reason`, each answer a runnable `afk` command (for `reason` both are the same one: the answer is its `--reason` text), `bulky: true` on one to delegate; with any open, `sleep_seconds` is 0. `errors` (when any) lists transitions that failed — `[{step, issue, error}]` — with their claims still held. The pass reads each thing once — the open PRs, the claim refs, a PR's turn comment — and what it writes is in every read after it; the workers it starts are begun in turn and then waited for together, and a start that cannot begin ends the starting for that tick. `state` is opaque and handed back verbatim; after a tick it holds the digest of the fleet as that tick left it (its own boards, refs and markers do not cause the next one) and which status board each claim already shows (an unchanged one costs no read); it carries `--instance` and `--worker-command`, which are passed on the first cycle only (no `--state`: a first cycle, always a tick) — a `state` without them, or one beside a different value of either, is exit 3. Sleep is `pace`'s: busy, or idle after three empty cycles. `--drain` is the run's **last** cycle — the launcher's stop: no gate, no pass; it releases every claim of mine that no open PR stands behind (a worker still coding, an orphan, a `closed` row) and keeps those with an open PR → `{action: drain, reason: stop, state, sleep_seconds: null, progress, judgments: []}`, a failed release in `errors` with its claim still held | effect + pure verdict |
| **Observation (read-only)** | | |
| `afk rebuild --instance <id>` | **one call → the whole working set**, from three reads made at once — every open issue (all pages, pull requests left out, each with its open-blocker count: no read per frontier candidate), the open PRs, the claim refs: frontier (dispatch+excluded), `mine` subclassified (`awaiting_turn` / `landing` / `joining` / `joined` / `fixing` / `awaiting_ci` / `failure` / `no_pr` / `landed` / `closed`) with PR/checks, the `attempt` it is on, `starting` (its failure is counted and the fresh worker has not started: a retry cut short, which the tick finishes with `afk fail`), and the `board_phase` it renders as, `peer_live`, `stale` (a dead peer's claim on an open issue, with the sha reclaim needs), `stale_closed` (a dead peer's claim on an issue already closed — a phantom lock — with the sha release needs), `free_slots`, fingerprint (ADR-0008). In `gate.ci: local` an open PR is `awaiting_turn` outright — no checks are read (ADR-0012) — or, where a **landing train** runs (no adversarial verify, ADR-0048), `joining` until its current head is on the train and `joined` from then on: read off the train's ref itself, never off a marker, so a PR whose worker pushed again is `joining` again; no turn is granted there and `merge_order` orders nothing. `merge_order` lists my ready PRs' issues in the order landing turns are granted: the PR that holds the turn first, then one that gave a turn up and is ready again, then the lower PR number. A PR that holds my landing turn is `landing`, and its row's `stopped` is the outcome its worker's last `afk land` stopped with, null while it has not stopped (ADR-0027). A PR that **gave my turn up** — its landing stopped `conflict` or `gate_red` on its first turn — is `fixing` while its worker fixes it off the turn, whatever its checks say (`stopped` says which; `board_phase` `fixing`): it holds no turn, is not in `merge_order`, and holds nobody's turn back. Ready again it is `awaiting_turn` with `board_phase` `ready_again` and takes its next turn first; a row's `given_up` says the PR gave a turn up once, whoever had granted it — on its next turn a `conflict` or a `gate_red` keeps the turn (ADR-0045). A claim of mine on an open issue that no open PR closes is `landed`, not `no_pr`, when the target — fetched once, and asked in this repo — holds the merge commit it joined the landing train with (ADR-0048): the landing's finishing was cut short after its push, and `afk release` finishes it | effect gather + pure assembly |
| `afk no-pr [--issue <n>] [--train] [--worktree <path>]` | **why my claims have no PR** — or, for a `landing` or `fixing` claim, whether its worker is still at it — for every such claim in one call → `{workers: [row per --issue]}`. Each worker's **worker state** is read first from `orca worktree ps` (its runtime's own report, checked against its terminal's output; ADR-0021): busy or gone is settled from that alone, no GitHub read (so its `turn_at` is null: not read). For a stopped worker it finds the issue's worktree through orca (`--worktree` overrides, one --issue only), reads its git progress against the remote base tip, the worker's latest `afk:verdict` marker, where each issue it says it is blocked by stands — the issue itself, the claim refs, the open PRs and the chain of open blockers under it (the cycle check) — and the landing turn on its PR → each row `{outcome, action, idle_seconds, pending_blockers, worktree, progress, worker_verdict, blockers, nudged_at, turn_at, worker_state}` (coding / idle_done / idle_blocked / idle_undecided / idle_stalled / idle_failed / dead; `worker_verdict` is the marker the worker posted — an input, not the conclusion; `blockers` is `[{number, standing: closed\|waiting\|unmet, reason}]`, and `idle_blocked` is `redispatch`, `park` or `escalate` by them — ADR-0022; `idle_undecided` / `escalate` is a `needs-decision` verdict: the issue's owner has a decision to make, and no attempt is spent on it — ADR-0041). A worker whose landing stopped for the tick (`awaiting_ci` / `needs_verify` / `no_checks`) is `coding` / `leave`: `afk turn` is what moves it. A `landing` claim's worker still silent after its nudge is `idle_stalled` / `restart` — a worker restarted onto the turn (`afk turn --restart`), not an attempt spent — once per turn: with the restart already on the turn marker the same silence is `idle_stalled` / `escalate` — the claim escalated with its PR, branch and worktree kept (`afk escalate`), never `idle_failed` / `next_attempt`: no silence of a `landing` claim reaches `afk fail` (ADR-0035). A `fixing` claim's worker — fixing off the turn its PR gave up — is on the same rungs: nudge, `restart`, `escalate` (ADR-0045). The tick supplies nothing but the issue numbers; an orca that cannot be asked is an error, never "gone". A `joining` claim's worker is on those rungs too. `--train` asks the same of the **train worker**, from the train's worktree → one row `{train, outcome, action, …}`: left while busy or within grace of when it was last told or of its last commit, started again by `afk turn --train` when gone, nudged once when silent, and silent again the train is abandoned (ADR-0048) | effect gather + pure verdict |
| `afk recovery --issue <n> [--branch <branch>] [--worktree <path>] [--no-worktree]` | what `afk dispatch` would continue from, without acting: a **dead** claim's recoverable progress → the tiered **continuation** verdict `{tier, action, prompt, reason, worktree, branch}` (worktree still here? branch ahead of base?). A remote that cannot be read is an error, never tier 3 — ADR-0011 | effect gather + pure verdict |
| **Act — one call per transition (ADR-0017)** | | |
| `afk dispatch --issue <n> --instance <id> --worker-command <cmd> [--ready-timeout <s>] [--start <auto\|fresh>]` | **start a worker**: claim (or confirm the claim is mine) → continuation tier → orca worktree at the right commit (the remote base tip, the pushed branch tip, or the worktree still here) → agent started with the worker launch command → prompt filled, delivered and submitted → status board. `{started: true, claim: won\|held, tier, action, prompt, worktree, branch, terminal}`, or `{started: false, claim: lost, owner}`. `--start fresh` discards the previous attempt first | effect + pure verdicts |
| `afk turn [--issue <n>] --instance <id> --worker-command <cmd> [--ready-timeout <s>] [--train] [--abandon] [--verified <head>] [--allow-no-checks] [--restart]` | **give a PR the landing turn** — the tick's half of a landing, one PR at a time (ADR-0027): refuse while another claim of mine holds the turn (`waiting`, with `holder`) or the tick's judgments are not in (the PR's checks in `required`, `--allow-no-checks`, `--verified <head>`) → write the landing brief → record the turn as ONE marker comment on the PR → deliver it — one submitted line to the worker's terminal, or, when that is gone, a new worker started by continuation in the same worktree (or one recreated at the PR's head), briefed only to land → status board. Run again on a `landing` row whose worker stopped for the tick, it tells that worker to land again (`again: true`). `{outcome: granted \| waiting \| landing \| fixing \| awaiting_ci \| gate_red \| no_checks \| needs_verify, pr, head, delivery: terminal\|continuation, terminal, worktree, comment_id}`. `fixing`: the PR gave its turn up and its worker is still fixing it off the turn — nothing is touched, and it is granted a turn only once its `afk land` says it is ready again (ADR-0045). It never merges, and there is no launcher-side merge fallback. **`--restart`** is for a `landing` row whose worker is still silent after its nudge (`no-pr` → `idle_stalled` / `restart`, ADR-0035): the idle session is closed and a worker is started by continuation in the same worktree (or one recreated at the PR's head, never from base), briefed only to land — the delivery a gone terminal gets — and the restart is written on the turn marker (`restarted`, also in the result). The PR, the branch, the worktree and the `afk-attempt/<n>` label are untouched; once per turn — a second call is refused, and a restarted worker silent again after its own nudge is escalated with the PR kept (`afk escalate`), never failed. A PR that holds no turn of mine is refused — but one that gave my turn up and is still being fixed has its silent worker replaced the same way, once: the restart is written on its marker, no turn is granted, and the outcome is `fixing` with `restarted` (ADR-0045). Where a **landing train** runs (`gate.ci: local`, no adversarial verify — ADR-0048) no PR is given a turn: `--issue` is refused with the reason. **`--train`** keeps the **train worker** on the train instead → `{outcome: idle \| landing \| granted \| stopped, train, tip, delivery: worker\|terminal, terminal, worktree}`: `idle` — nothing is on the train; `landing` — its worker is at work; `granted` — a train worker was started in the train's worktree (one per repo, cut when this machine has none, and kept), or the one that had stopped was told that more joined; `stopped` — it stopped and nothing joined since it was told (`afk no-pr --train` says why). **`--abandon`** gives the train up with nothing landed, after its worker stayed silent past its nudge: each PR of mine on it is marked (`abandoned=` on its turn comment) and its worker told to join the next train — one already marked is escalated instead, everything kept — the train's refs are deleted and its worktree cleared and kept → `{outcome: abandoned, train, issues, escalated, told, worktree}`. What the train already pushed to the target has landed and is not touched | effect + pure verdicts |
| **The worker's own** | | |
| `afk gate [--train] [--gate-timeout <s>]` | **a worker's run of the local gate**, in the worktree it is called from — never run by a tick. Runs `gate.local_command`, streams its log to the terminal (stderr), and on **green**, on a committed tree, puts the run on record on the remote — one ref, `refs/afk/gate/<tree>-<hash of the command>`, named for the tree it tested; a red or timed-out run leaves no record (and deletes that tree's). `{status: green \| red, exit_code, timed_out, command, head, recorded, detail}` — `recorded` is true only for a green run on a worktree that was exactly its commit before the run and after it — nothing uncommitted or untracked, no tracked file rewritten by the gate (`uncommitted` lists what was) — whose record was written (`not_recorded` says why it was not: the worker goes on, and the landing gates), the one kind `afk land` trusts (ADR-0030). `afk land` and `afk land --train` hold their own run to the same rule: one that was not of the committed tree is refused with an `error` naming the paths — nothing merged, nothing recorded. **`--train`**, where a landing train runs (ADR-0048), first merges into the branch what the PR will land behind — the train's tip; while the train is red, its last green commit; the target when there is neither — never a rebase (`merged` in the result): a green run is then of the tree the PR joins with, and the train needs no second run for it. A merge that conflicts is left in progress and no gate runs: `{status: conflict, files, recorded: false}`. The worker prompt carries the whole line, config included | effect + pure verdict |
| `afk land [--issue <n>] [--train] [--gate-timeout <s>] [--excerpt-lines <k>] [--merged-timeout <s>] [--checks-timeout <s>] [--checks-poll <s>]` | **a worker lands its own PR**, in the worktree it is called from — never run by a tick, and the only way a PR lands (ADR-0027). Exit 3, nothing changed, unless the PR holds the landing turn of the fleet instance that holds the issue's claim — or gave that turn up, in which case it runs **off the turn**: the push and the sync below, no local gate (ADR-0047) and no merge. **Where a landing train runs** (`gate.ci: local`, no adversarial verify — ADR-0048) it needs no turn and runs no gate: it **joins the train** — push what the worker committed → the PR's head merged onto the train's tip with ONE merge commit (`Title (#pr)`, `Closes #issue`; made without touching the worktree) → that commit pushed as the train's new tip (the only lock: lost to another join, it is made again on the new tip) → status board. `{outcome: joined \| conflict \| merged, pr, head, commit, again}`: `joined` — the PR is on the train (`again` when it already was), the worker wakes the launcher and stops; `conflict` — the train's tip was merged into the branch and left in progress with `files`, resolved once, against a train that is never rewritten; `merged` — the head is already on the target. **Everywhere else**: sync (merge the target in, never rebase) → push → the configured machine gate on that head (in `local`: run here, or not run again when a green run of the configured command is on record on the remote for that head's tree, wherever it was made — `gate.source: run \| recorded`, ADR-0030; in `required`: the PR's checks on that head, **waited for here** — re-read every `--checks-poll` seconds, default 15, for at most `--checks-timeout`, default 1800 — whenever the sync pushed a new head, they are still running, or the PR as first read was not at that head) → adversarial-verify check → the turn and the target's tip **read again** (a gate run or a wait for checks is long) → `gh pr merge` pinned to the gated head → status board. `{outcome: merged \| conflict \| gate_red \| target_moved \| awaiting_ci \| needs_verify \| no_checks \| awaiting_turn, turn: held\|given_up, pr, head, synced, gate, …}`: `conflict` leaves the merge in progress with `files` for the worker to resolve and commit; `gate_red` is the worker's to fix — and the first time a PR's landing stops with either, it **gives the turn up** (`turn: given_up`; the marker gains `given_up=<epoch> released=1`, the claim is `fixing`): the worker sends one wake and keeps fixing, and run again off the turn the command syncs, stops `conflict` as often as it takes (`required`: or `gate_red`, on red checks), runs no local gate and merges nothing, and answers `awaiting_turn` once the PR merges with the target cleanly — the PR is ready again, its gate run left to its next turn (ADR-0047), the worker wakes the launcher and stops. On the PR's next turn the two keep the turn (ADR-0045); `target_moved` is a target that moved under the gate — a tip the gated head no longer holds — nothing merged, and the same command run again gates on the new tip; a turn that is no longer the one this landing started on (the claim released or taken over, the turn granted afresh) is exit 3 again, nothing merged and nothing written; `awaiting_ci` is only what the wait for checks says when its bound runs out; on `awaiting_ci` / `needs_verify` / `no_checks` the worker wakes the launcher and stops, and the tick's next `afk turn` tells it to land again. No outcome spends an attempt; each one but `merged` is written onto the PR's turn comment. It releases no claim and removes no worktree — the next cycle's `closed` row does. The landing brief carries the whole line, config included. **`--train`** is the **train worker's** landing, in the train's worktree (ADR-0048) — which keeps no list of the train's PRs: they are read, on every run, from the join commits on the train's ref. Take the train's tip (merged in when this worktree holds a fix commit of its own) → merge the target in when it moved from outside, never a rebase → push that as the train's tip → the gate ONCE on it (not at all when that tree is already on record green — a train of one lands on its worker's own run) → push it to the target as a fast-forward (a target that moved refuses it) → per PR landed: status board, issue closed; GitHub shows each PR merged by itself, and its branch is deleted once it does (waited for up to `--merged-timeout`; `unmerged` lists the PRs still open then, left with their branches). `{outcome: landed \| idle \| gate_red \| conflict \| target_moved, train, target, commit, prs, gate, landed: [{issue, pr, commit}], unmerged, more}`: `landed` is run again at once (`more` says the train grew meanwhile); `idle` — nothing is on the train; `gate_red` is fixed with one more commit on top and run again, the excerpt also a comment on every PR of that run; `conflict` is resolved here and committed; `target_moved` is run again. Nothing lands on any outcome but `landed` | effect + pure verdicts |
| `afk nudge [--issue <n>] --instance <id> [--train] [--worktree <path>]` | **tell a silent worker to carry on** (`no-pr` → `idle_stalled`): read the last screen of its terminal, type one line at it, record the nudge in the worktree's git dir → `{action: nudged, terminal, terminal_tail}`. Once per worker — a second call is refused; no attempt is spent, nothing is discarded (ADR-0018). `--train` nudges the landing train's worker the same way, once | effect |
| `afk fail --issue <n> --instance <id> --worker-command <cmd> [--ready-timeout <s>] --reason <text>` | **the retry ladder**: read the attempt off the issue, then `retry` (swap the `afk-attempt/<n>` label up by one and add `afk-attempt/starting` in one edit, discard the failed attempt's PR + branch + worktree, start a fresh worker handed `--reason`, remove `afk-attempt/starting`) or `escalate` (as below) → `{action, attempt, …}`. Run again on a failure already counted — the issue still carries `afk-attempt/starting` — it finishes that retry and adds nothing: one failure, one attempt. Run again on a failure whose escalation was cut short — the claim still held, its escalation comment on the issue — it finishes that escalation and never retries, though the relabel has stripped the count (ADR-0033). After an unanswered nudge the worker's last screen is appended to the reason. A `landing` claim's silence never comes here — it is restarted onto its turn, then escalated (ADR-0035); `fail` reaches a landing claim only by the tick's own judgments | effect + pure verdict |
| `afk escalate --issue <n> --instance <id> --reason <text>` | **hand a claim to a human**, in one order: status board → comment, under the record of whose escalation it is (`<!--afk:escalation claim=… attempt=…-->`) → relabel (`escalate_label` on; `ready_label` and attempt labels off) → release the claim → remove the worktree when its branch holds no work (one with commits or a dirty tree is kept, as `park` keeps it) — for a blocker nothing will resolve (`no-pr` → `idle_blocked` / `escalate`), a decision only the issue's owner can make (`no-pr` → `idle_undecided` / `escalate`, ADR-0041), or a landing — on its turn, or being fixed off one its PR gave up — silent again past its one restart (`no-pr` → `idle_stalled` / `escalate`, ADR-0035, ADR-0045): the PR stays open, the branch and the worktree stay, no attempt is spent, and a released claim holds no turn, so the next PR's `turn` is `granted`. After an unanswered nudge the worker's last screen is appended to the reason, as `fail` appends it | effect |
| `afk park --issue <n> --instance <id>` | **wait on a dependency the worker discovered** (`no-pr` → `idle_blocked` / `park`), in one order: a native `blocked_by` edge to each named blocker still open → status board → release the claim → remove the worktree when its branch holds no work (one with commits or a dirty tree is kept). `{action: parked, blocked_by, edges_added, released, cleanup}`. `ready_label` and the attempt labels are untouched; the frontier excludes the issue until its blockers close. Re-reads the blockers and refuses a claim that is not parkable (ADR-0022) | effect + pure verdict |
| `afk close --issue <n> --instance <id>` | **close an issue that needed no change** (after the tick verified the empty diff): status board → close → release → worktree cleanup | effect |
| `afk status <n> --phase <phase> [--instance <id>] [--pr <pr>] [--attempt <k>]` | upsert the human-facing progress **status board** comment at a non-terminal phase, idempotently. `<phase>` is a `mine` row's `board_phase`; `<k>` is the row's `attempt`; `retry_max` and the gate's name come from config. (The terminal phases are written by `land` / `escalate` / `park` / `close`, `landing` by `turn`.) | pure render + effect |
| **Claim refs** | | |
| `afk reclaim <n> --instance <id> --expect-sha <sha>` | `--force-with-lease` take of a stale claim → `{won}`. For a `stale` row; a `stale_closed` one is released instead | effect |
| `afk takeover --instance <id> [--list] [--from <dead-id>] [--yes]` | the fleet instances GitHub remembers (claim markers + heartbeat refs) with heartbeat age / host / claim count — or force-take a dead one's claims: same atomic push as `reclaim`, staleness gate skipped, a fresh-heartbeat target held back until `--yes` (ADR-0011). `--instance` is always **my** id | effect + pure verdict |
| `afk release <n> --instance <id> [--expect-sha <sha>]` | delete a claim ref → `{released: true}` (idempotent: already gone counts). A delete that left the claim on the remote is an error. For the cases no transition covers. Without `--expect-sha`, a claim of **mine** — an orphan-release, a `closed` or `landed` row, the drain; a claim another instance holds is refused, and the delete is leased to the sha the scan showed, so a claim a peer took since is left alone and is an error (it is no longer the caller's). A `landed` row's issue — open, though the landing train landed it — is closed first, its status board set to merged, and it is then settled as a closed one. A claim whose issue is closed — the `closed` row a landed PR leaves — has its worktree removed too (`cleanup`); an open issue's worktree is never touched; and a PR the landing train landed that GitHub still does not show merged is closed here, with the comment naming its commit (`closed_pr`, ADR-0034, ADR-0048); and the local `base_branch` branch of the fleet's own checkout is fast-forwarded to what landed (`synced`: `{branch, tip, updated}` or `{branch, skipped}`, ADR-0037) — all of it before the claim is deleted, so a run that raised on the way still holds the claim and the next tick releases it again.
